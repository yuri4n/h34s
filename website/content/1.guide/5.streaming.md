`ZHandler.sendStream` sends a ZIO stream through h3. The current adapter supports direct Node HTTP responses, including requests made with a browser's `fetch`.

This guide covers the ZIO adapter. The [Kyo handler slice](/guide/kyo) handles ordinary response values and request cleanup; a Kyo streaming adapter remains planned.

## Send a stream

The repository's database-free endpoint is:

```scala
import dev.yuri4n.exts.zioh3.ZHandler
import zio.stream.ZStream

import scala.scalajs.js.annotation.JSExportTopLevel

@JSExportTopLevel("default", "test")
val handler = ZHandler.define:
    ZHandler.sendStream(ZStream("a", "b", "c"))
```

The source is `scala-modules/svr/src/main/scala/dev/yuri4n/svr/handlers/TestHandler.scala`. After [starting the example](/guide/getting-started), make a direct HTTP request:

```sh
curl --fail --no-buffer http://127.0.0.1:3000/api/test
```

The response body is `abc`. This example sends text; it does not define an SSE protocol or JSON event envelope. HTTP clients can combine or split writes, so do not rely on one client-visible chunk per emitted string.

`sendStream` waits for h3 to consume the source stream. The handler returns native JavaScript `undefined` rather than a separate response value.

## Keep resources alive during transfer

`ZHandler.define` owns the request scope. `sendStream` waits for h3's stream operation, keeping request resources alive until h3 consumes the source or the operation is interrupted. Node can still have outgoing data buffered at that point; completion does not confirm client receipt.

The adapter pulls one upstream chunk at a time. Normal completion and failure close its stream scope. Cancellation interrupts active upstream work and waits for cleanup. A Node response close also interrupts the stream and releases request resources.

Keep resource acquisition inside a scope that covers the transfer. If application code closes a resource before calling `sendStream`, the adapter cannot restore it. The [application environment](/guide/handlers#compose-services-once-in-application-code) can provide scoped services around the whole handler.

## Handle failures after output begins

Before a response is committed, the normal [error boundary](/guide/handlers#choose-what-a-client-may-see) can produce an error response.

After headers have been sent, a stream failure destroys the response. Appending a JSON error document would corrupt the existing body. Clients should therefore handle a failed or incomplete transfer, even when the initial status was successful.

## Current transport limits

| Area                            | Current behavior                                         |
| ------------------------------- | -------------------------------------------------------- |
| Direct Node HTTP                | Supported by this adapter                                |
| Nitro no-socket local-fetch     | Explicitly rejected                                      |
| Other Nitro deployment adapters | Require separate lifecycle implementation and validation |
| Adapter queue                   | Pull-driven; bounded by upstream chunk size              |
| Complete HTTP buffering         | No end-to-end memory bound is established                |

Nitro's no-socket local-fetch path returns a stream before the consumer finishes reading it. That path cannot preserve the request scope with the current API. Use direct HTTP for stream responses rather than an in-process server fetch.

The adapter's pull behavior also does not bound every outgoing buffer. h3's Web Stream sink does not await Node response `drain`, so a slow client can still grow Node's outgoing buffers.

## Check lifecycle behavior

Run the library tests from the repository root:

```sh
sbt 'zioH3Ext/test'
```

The suite covers stream completion, failure, cancellation, scoped cleanup, and response-close behavior using real h3 with mocked Node responses. The HTTP smoke check verifies the `abc` response against a running Nuxt instance.

An actual client-abort integration check remains to be added. See [status](/reference/status) before extending these guarantees to another transport or deployment adapter.
