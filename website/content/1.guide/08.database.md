h34s has no database module, on purpose. Good PostgreSQL clients already run in Scala.js on Node. Use kyo-sql in a Kyo application and Skunk in a ZIO application, directly, and plug them into your `AppHandler`:

1. Read the connection settings with `RuntimeConfig.load` or `ZRuntimeConfig.load`, with the password in a `Secret` ([configuration](/guide/configuration)).
2. Open one pool per application in `Shared` or `ZShared` ([lifetimes](/guide/lifetimes)).
3. Run each request's statements in one transaction or one pooled session.
4. Map the database errors a client may see, such as a unique violation, to your own `SafeError` inside the service. Every other database error stays an opaque 500.

Create tables with your own migration tool. Handlers never change the schema.

## Kyo: kyo-sql and kyo-sql-postgres

> **Status: compiles, never run.** This code compiles against kyo-sql-postgres 1.0.0-RC7 and the h34s API on this branch. It has not been run against a database or inside Nitro, and nothing in the repository uses kyo-sql yet.

Add `"io.getkyo" %%% "kyo-sql-postgres" % "1.0.0-RC7"`. Declare the URL as a private runtime config key and set `NUXT_DATABASE_URL` at runtime:

```scala
final case class DatabaseConfig(url: Secret, verifyTls: Boolean) derives NativeConverter
final case class AppConfig(database: DatabaseConfig) derives NativeConverter
```

kyo-sql 1.0.0-RC7 parses `postgres://user:password@host:5432/db` itself, with these rules (from its source):

- **The port is required.** Add `:5432` when a provider leaves it out.
- **Credentials are not percent-decoded.** `p%40ss` is sent as those exact characters.
- **`sslmode=require` encrypts but does not verify** the certificate or host name. `verify-ca` and `verify-full` need `sslrootcert`, a file path. To verify against the system store, set the TLS settings in code, as below.

Open one pool for the application:

```scala
object Database:
    /** One pool for all requests: opened on first use, closed when Nitro closes. */
    val client: Shared[PostgresClient] = Shared(
      RuntimeConfig.load[AppConfig].map { config =>
        val sqlConfig =
          if config.database.verifyTls then
              SqlConfig.default.tlsMode(SqlConfig.TlsMode.Require).tls(NetTlsConfig.default)
          else SqlConfig.default
        PostgresClient.init(config.database.url.reveal, sqlConfig)
      },
    )
```

Run one transaction per request and map the errors your client may see:

```scala
final case class DuplicateNote() extends SafeError:
    def message: String      = "A note with this text already exists"
    override def status: Int = 409

final class NotesLive(client: PostgresClient):
    def create(text: String): Note < (Async & Abort[DuplicateNote | SqlException]) =
      Abort.recover[SqlServerConstraintViolationException](error =>
        if error.sqlState == "23505" then Abort.fail(DuplicateNote()) else Abort.fail(error),
      )(DB.run(client)(DB.transaction(
        sql"INSERT INTO notes (text) VALUES ($text) RETURNING id, text".as[Note].run.map(_.head),
      )))
```

`sql"..."` binds `$text` as a parameter. `DB.transaction` rolls back on any failure. Never use `DB.run(url)` per request: it opens a whole pool each time. Never put `SqlException` details in a `SafeError`: they can contain database values.

kyo-net prefers native I/O backends loaded through FFI and falls back to Node's `net`/`tls`. In Nitro, force Node with `KYO_NET_BACKEND=node`. **Unverified:** kyo-sql has not run inside a Nitro bundle with h34s, and non-Node presets have no `net`/`tls`.

## ZIO: Skunk in a ZShared layer

The demo's Notes example uses Skunk 1.0.0-M12. The code compiles and its handlers are unit-tested. A production build of the demo loaded the configuration, built the pool and released it on `SIGTERM`, but no PostgreSQL server was available: the insert and read flow has not been run on this branch.

Settings come from `runtimeConfig.database`: `NUXT_DATABASE_HOST`, `NUXT_DATABASE_PORT`, `NUXT_DATABASE_USER`, `NUXT_DATABASE_PASSWORD`, `NUXT_DATABASE_NAME`.

`SessionPool.scala` opens one pool from the startup config:

```scala
object SessionPool:
    /** Reads the startup runtime config and creates the pool. Connections open on first use. */
    val layer: ZLayer[Any, Throwable, SessionPool] =
      ZLayer.scoped(
        for
          config   <- ZRuntimeConfig.load[AppConfig]
          sessions <- pooled(config.database).toScopedZIO
        yield SessionPool(sessions),
      )
```

`pooled` builds a `Session.Builder[Task]` with host, port, credentials (an empty password means none) and `.pooled(max = 4)`. `AppHandler` shares it with `ZShared.layer(SessionPool.layer)`, and each request takes one session in its scope:

```scala
final class NotesLive(session: Session[Task]) extends Notes:
    private val codec = (int4 *: text).to[Note]

    def create(value: String): Task[Note] =
      session.unique(sql"INSERT INTO h34s_notes (text) VALUES ($text) RETURNING id, text".query(codec))(value)

    def list: Task[List[Note]] =
      session.execute(sql"SELECT id, text FROM h34s_notes ORDER BY id".query(codec))

object NotesLive:
    /** Notes over one pooled session that lives as long as the request scope. */
    val layer: ZLayer[SessionPool & Scope, Throwable, Notes] =
      ZLayer.fromZIO(ZIO.serviceWithZIO[SessionPool](_.session).map(NotesLive(_)))
```

The demo builds `NotesLive.layer` before the handler runs, so each Notes request takes a session before it reads the body: with the database down, even invalid input gets a 500. To return input errors first, read and validate the body before you take a session.

For a transaction, open Skunk's `session.transaction` resource in the same request scope. To map a unique violation, match `case SqlState.UniqueViolation(_) =>` in the service. The demo does not use these two recipes.

Skunk 1.0.0-M12 calls `require('crypto')` for SCRAM authentication. Copy the demo's Nitro plugin `examples/nuxt/server/plugins/skunk-node-crypto.ts` into your app. If authentication ran before the plugin was installed, restart the server.
