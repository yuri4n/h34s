Every resource needs an owner. h34s gives you two lifetimes:

| Lifetime | Use it for | Kyo | ZIO |
| --- | --- | --- | --- |
| One request | A pooled session, a transaction, a stream's source | the request `Scope` in `HandlerEffects` | the request `Scope` in `HandlerEnv` |
| The application | A connection pool, an HTTP client | `Shared` | `ZShared` |

> **Status.** `Shared` and `ZShared` are part of `0.2.0-SNAPSHOT` (unreleased).

## Request resources

Acquire with Kyo's `Scope.acquireRelease` or ZIO's `ZIO.acquireRelease` inside the handler. h34s releases them:

- for a value or `Unit` body, after your program and before the response settles (asynchronous finalizers included);
- for a streamed body, after the stream ends, fails or is cancelled;
- when the client disconnects: h34s interrupts your program, waits for the finalizers, and writes nothing.

The demo takes one pooled Skunk session per request:

```scala
object NotesLive:
    /** Notes over one pooled session that lives as long as the request scope. */
    val layer: ZLayer[SessionPool & Scope, Throwable, Notes] =
      ZLayer.fromZIO(ZIO.serviceWithZIO[SessionPool](_.session).map(NotesLive(_)))
```

A failing Kyo `Scope` finalizer is logged and keeps the response. A ZIO finalizer that dies turns a value response into a 500. Put work that must affect the response in the program, not in a finalizer.

## Application resources

`Shared` and `ZShared` hold one resource for all requests:

- the first `get` acquires it, and concurrent first calls share one acquisition;
- a failed acquisition is not cached;
- a cancelled request does not cancel an acquisition others wait for;
- a successful acquisition registers with the Nitro close hook;
- `close` releases it; a later `get` acquires it again.

Declare one in an `object`. Nothing runs until the first `get`:

```scala
object Resources:
    val pool: Shared[Pool] = Shared(
      Scope.acquireRelease(openPool)(pool => closePool(pool)),
    )
```

`openPool`, `closePool` and `Pool` stand for your code. For ZIO, wrap any layer, as the demo's `AppHandler` does:

```scala
private val database = ZShared.layer(SessionPool.layer)
```

Then `database.provide(program)` supplies it. Load settings inside the acquisition with `RuntimeConfig.load` or `ZRuntimeConfig.load`.

Every handler linked from the same sbt project shares one copy of a `Shared` value. Two separately linked projects have two copies.

## When Nitro closes

The h34s plugin releases every registered `Shared` and `ZShared` on Nitro's `close` hook; one failing release does not stop the others. In Nitro 2.13 the `node-server` preset calls that hook on `SIGTERM` and `SIGINT` (30-second graceful shutdown by default), and `nuxt dev` calls it when it replaces its worker. These facts come from Nitro's source; h34s tested the release path with a fake plugin record, not a real shutdown.

Without the plugin (for example in unit tests), nothing registers. Call `close` yourself.
