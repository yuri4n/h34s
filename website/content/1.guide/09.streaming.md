Return a stream as the response body. h34s sends its elements as they are produced, keeps the request scope open until the stream ends, and, when the client disconnects, stops the stream and waits for its cleanup.

> **Status.** Stream bodies are part of `0.2.0-SNAPSHOT` (unreleased). They replace `ZHandler.sendStream`.

## Return a stream

Kyo, any `kyo.Stream[A, S]` with a `NativeConverter[A]` and `S` within `Async & Abort[Throwable] & Scope`:

```scala
val letters: EventHandler = KHandler.define: _ =>
    Response.status(Status.Accepted)
      .andThen(Response.header("content-type", "text/plain"))
      .andThen(Stream.init(Seq("a", "b", "c")))
```

ZIO, any `ZStream[Any, E, A]` with `E <: Throwable` and a `NativeConverter[A]`:

```scala
val letters: EventHandler = ZHandler.define(_ =>
  Response.status(Status.Accepted) *> Response.header("content-type", "text/plain") *> ZIO.succeed(ZStream("a", "b", "c")),
)
```

Both send `abc` with status 202 (from the stream tests).

## What reaches the client

- The head is written before the first element, or before an empty stream ends.
- Each element is converted and written as is: no envelope, no separator, no content type. Set `content-type` yourself.
- String elements are tested over HTTP. Encode NDJSON or Server-Sent Events yourself, one string per element.
- Clients may merge or split writes; do not rely on one chunk per element.

## Keep resources alive

Acquire what the stream needs in the request scope (Kyo `Scope.acquireRelease`, ZIO `ZIO.acquireRelease`), or let the stream own them (`ZStream.unwrapScoped`, `ZStream.acquireReleaseWith`). h34s closes the scope only after the stream ends, fails or is cancelled.

## Cancellation

One producer fiber pulls your stream, one chunk at a time, only when the HTTP side asks. When the client disconnects, h34s interrupts the producer, waits for the stream's finalizers (asynchronous ones too), then closes the request scope, once. A response that closed before the stream started never starts it.

## Failures

| When the stream fails | Result |
| --- | --- |
| Before the first element | The normal failure rule: an approved `SafeError` or an opaque 500 |
| After the first element | The socket is destroyed; written elements stay; the client sees an incomplete transfer; the server logs it |
| An element converter throws, even a `SafeError` | A defect |

Clients should treat an interrupted transfer as a failure, even after a 2xx status.

## Limits

| Area | Behavior |
| --- | --- |
| Direct Node HTTP | Supported; tested with real h3 and mocked Node responses |
| No socket (Nitro's in-process local fetch) | Rejected before acquiring stream resources: an opaque 500 |
| Back pressure | One chunk at a time, but h3 does not wait for Node's `drain`: no end-to-end memory bound |
| Serverless and edge presets | Not tested |

Tested in both runtimes: pull-driven delivery, head before the first chunk, empty streams, finalization once, cancellation waiting for asynchronous finalizers, disconnects, failures before and after the first chunk, converter defects and the no-socket rejection. A real client abort against a running Nuxt server has not been tested on this branch.
