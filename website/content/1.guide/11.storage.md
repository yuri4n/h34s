Use key-value storage from Scala without JavaScript. `KHubKv.mount(base)` (Kyo) and `ZHubKv.mount(base)` (ZIO) open the same storage that Nitro's `useStorage(base)` returns. You do not import `@nuxthub/kv` or pass a native object.

> **Status.** `mount` is part of `0.2.0-SNAPSHOT` (unreleased). It replaces the `KHubKv(native)` and `ZHubKv(native)` constructors.

Add `kyo-nuxthub-ext` (Kyo) or `zio-nuxthub-ext` (ZIO). Neither needs a schema.

## Choose a mount

Configure mounts with Nitro's `storage` option, or let a module add them:

```ts
export default defineNuxtConfig({
  modules: ['@yuri4n/h34s-nuxt'],
  nitro: {
    storage: {
      cache: { driver: 'redis', url: process.env.REDIS_URL },
    },
  },
})
```

Keep connection URLs out of committed files. `mount("")` opens the root storage.

Whether NuxtHub 0.10.8 exposes its KV as a Nitro storage mount has not been verified. The bindings were tested with Unstorage 1.17.3's memory driver, which NuxtHub 0.10.8 generates for local KV. Check the mount name in your setup.

## Use it

```scala
final case class Profile(name: String, visits: Int) derives NativeConverter

// Kyo
val visit: Option[Profile] < (Async & Abort[Throwable]) =
  for
    cache   <- KHubKv.mount("cache")
    _       <- cache.set("profiles:42", Profile("Yuri", 1), ttlSeconds = Some(300.0))
    profile <- cache.get[Profile]("profiles:42")
  yield profile

// ZIO
val visitZio: Task[Option[Profile]] =
  for
    cache   <- ZHubKv.mount("cache")
    _       <- cache.set("profiles:42", Profile("Yuri", 1), ttlSeconds = Some(300.0))
    profile <- cache.get[Profile]("profiles:42")
  yield profile
```

Both offer `get`, `set` (with an optional TTL in seconds), `has`, `delete` and `keys`. Each run calls the storage again. `mount` fails with `ConfigError` when the plugin or the mount is missing.

## Know the contract

- A missing key and a stored `null` are both `None`; use `has` when the difference matters.
- Unstorage can turn a stored top-level string such as `"42"` into another type. Store case classes.
- A stored value that does not decode fails `get` with `StoredValueError`, which names only the path, never the key or the value. Unhandled, it is an opaque 500, not a 422.
- TTL support depends on the driver. The memory and fs-lite drivers ignore it.
- Keys are normalized: `/` becomes `:`. `keys(Some("profiles"))` lists `profiles:*`.
- Storage calls cannot be cancelled. An interrupted fiber does not undo a write that already started.

h34s adds no cache layer. Delete keys after writes, put a generation number in your keys to invalidate many at once, or use short TTLs on drivers that support them.

Tested with 15 Kyo and 14 ZIO tests: mounting through a fake plugin record, round trips, `null`/`undefined`, lazy operations, TTL forwarding, failures, value-free decode errors and interruption. No test starts Nuxt, NuxtHub or a cloud service.
