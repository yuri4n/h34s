The ZIO API is a first-class adapter over the Kyo core. You write ordinary ZIO: `for` comprehensions, `ZIO.service`, typed errors, `ZLayer` and `ZStream`. `ZHandler.define` runs your program on a ZIO `Runtime` and hands the result to the core, which owns the lifecycle, the wire format and the response.

Your application depends on `zio-h3-ext`, which brings Kyo with it. You never write Kyo code in a ZIO application.

> **Status.** This page describes `0.2.0-alpha.1`. The older `0.1.0-alpha.1` ZIO API is different; the [migration guide](/reference/migration) maps every call.

Build with Scala 3.9.0 and JDK 25, keep ZIO at 2.1.26 (pinned by kyo-zio), and import `dev.yuri4n.exts.zioh3.*`.

## Write a handler

The demo's database-free route (`examples/nuxt/scala/zio/.../TestHandler.scala`):

```scala
import dev.yuri4n.exts.zioh3.{EventHandler, ZHandler}
import zio.ZIO
import zio.stream.ZStream

import scala.scalajs.js.annotation.JSExportTopLevel

@JSExportTopLevel("default", "test")
val handler: EventHandler = ZHandler.define(_ => ZIO.succeed(ZStream("a", "b", "c")))
```

`GET /api/test` returns `abc`.

## Keep handler functions small

Keep each handler as a value, so a test can call it (`NotesHandler.scala`; `Notes`, `NoteView`, `CreateNote` and `AppHandler` are demo code):

```scala
object NotesHandler:
    val list: Request => ZIO[Notes, Throwable, List[NoteView]] =
      _ => ZIO.serviceWithZIO[Notes](_.list).map(_.map(NoteView.from))

    /** The schema validates and trims the input before any database work. */
    val create: Request => ZIO[HandlerEnv & Notes, Throwable, NoteView] = request =>
      for
        input <- request.body.json[CreateNote]
        note  <- ZIO.serviceWithZIO[Notes](_.create(input.text))
        _     <- Response.status(Status.Created)
      yield NoteView.from(note)

@JSExportTopLevel("default", "notes-post")
val createNote: EventHandler = AppHandler.define(NotesHandler.create)
```

## Request and response

The `Request` snapshot, body rules and status codes are the same as in [Kyo handlers](/guide/kyo#read-the-request). The ZIO types:

| Call                                                                                                                     | Type                               |
| ------------------------------------------------------------------------------------------------------------------------ | ---------------------------------- |
| `request.body.json[A]`                                                                                                   | `IO[HttpError \| InvalidInput, A]` |
| `request.body.text()`                                                                                                    | `IO[HttpError, String]`            |
| `request.param(name)`                                                                                                    | `IO[HttpError, String]`            |
| `Response.status`, `header`, `appendHeader`, `cookie`, `deleteCookie(name, path, domain, secure, onFailure)`, `redirect` | `URIO[ZState[ResponseHead], Unit]` |

Bodies: a value with a `NativeConverter` (`{"data": ...}`), `Unit` (204), or a `ZStream[Any, E, String]` with `E <: Throwable` ([streaming](/guide/streaming)).

The head lives in a `ZState`, which is backed by a `FiberRef`: a forked fiber works on its own copy, and joining it copies the child's head back. `catchAll` does not roll back head changes. Set response entries in the request fiber when you can.

## Fail safely

| Failure                                      | Status       | Body                                               |
| -------------------------------------------- | ------------ | -------------------------------------------------- |
| `ZIO.fail(safeError)`                        | its `status` | `{"errors":[{"message":"..."}]}`                   |
| `ZHandler.failWith(status, msg, msgs*)`      | `status`     | one entry per message                              |
| `InvalidInput` from a body read              | 422          | entries with `path`                                |
| Any other failure, a defect, or interruption | 500          | `{"errors":[{"message":"Internal server error"}]}` |

<!-- claude 2026-10-19: changed: a dying ZIO finalizer is logged and keeps the response (issue #40); the request-scope boundary (review) -->

Failing with an arbitrary `Throwable` does not make it public. Map it to your own `SafeError`. `ZHandler.failWith` fails with `ErrorResponse`, which is not a `SafeError`: `catchSome { case e: SafeError => ... }` does not catch it, but h34s approves both. A ZIO finalizer that dies is logged (`h34s: a ZIO finalizer failed`) and does not change the response, as in Kyo. This covers the request scope; a release that dies inside your own `ZIO.scoped` block or a scoped layer you provide inside the handler fails the program and answers 500, as before. In development or debug mode, diagnostics of a failed program show ZIO's full `Cause.prettyPrint`.

`ZHandler.define(options)` takes the same `HandlerOptions` as Kyo:

```scala
ZHandler.define(HandlerOptions(defaults = ResponseHead.noStore)): request =>
  ...
```

## Wire layers in your AppHandler

The demo's `AppHandler` shares one Skunk pool and provides `Notes` per request:

```scala
object AppHandler:
    private val options = HandlerOptions(defaults = ResponseHead.noStore)

    /** One Skunk pool for all requests: built on first use, released when Nitro closes. */
    private val database = ZShared.layer(SessionPool.layer)

    def define[B: ZResponseBody](program: Request => ZIO[HandlerEnv & Notes, Throwable, B]): EventHandler =
      ZHandler.define(options): request =>
          database.provide(program(request).provideSomeLayer[HandlerEnv & SessionPool](NotesLive.layer))
```

`HandlerEnv` is `ZState[ResponseHead] & Scope`. The `Scope` is the request scope; it stays open while a streamed body is sent. A plain `ZLayer` is rebuilt every time you provide it, so wrap shared resources in `ZShared` ([lifetimes](/guide/lifetimes)).

`ZHandler.define` uses `Runtime.default` unless a `given Runtime[Any]` is in scope. You do not need to create one.
