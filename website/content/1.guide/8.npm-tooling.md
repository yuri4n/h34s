`@yuri4n/h34s-nuxt` packages the reusable build CLI, development loading, source maps, and Nuxt development-error plugin. Your application keeps its Scala build, models, services, route mounts, and database migrations.

**[`@yuri4n/h34s-nuxt@0.1.0-alpha.1` is published](https://github.com/yuri4n/h34s/releases/tag/npm-v0.1.0-alpha.1)** in the private GitHub npm registry. Its `npm-v0.1.0-alpha.1` tag is separate from the immutable Maven `v0.1.0-alpha.1` release.

## Install the build dependency

Configure the private GitHub npm registry in `.npmrc`:

```ini
@yuri4n:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${GITHUB_PACKAGES_TOKEN}
```

For GitHub Actions, save the token as `PACKAGES_READ_TOKEN`, then map `${{ secrets.PACKAGES_READ_TOKEN }}` into the `GITHUB_PACKAGES_TOKEN` environment variable. GitHub reserves the `GITHUB_` prefix for saved secret and variable names.

Provide a classic PAT with `read:packages` and private package access through your environment or secret manager. Commit the placeholder, never its value. The npm registry and sbt's Maven resolver need separate configuration.

```sh
pnpm add -D @yuri4n/h34s-nuxt@0.1.0-alpha.1
pnpm add h3@1.15.4
```

For local source review, run `npm pack ./packages/nuxt --pack-destination /tmp` from the h34s checkout, then install `/tmp/yuri4n-h34s-nuxt-0.1.0-alpha.1.tgz` as a dev dependency in a disposable consumer. The repository example already consumes the local package.

The release workflow downloads the published archive with registry authentication, verifies that its bytes match the tested tarball, then installs it offline in a clean consumer and checks the CLI and all three JavaScript entry points. The release attaches the archive and `registry.json` with its stable registry URL and integrity.

Nuxt 4.3.1 passes the packed-package development and production HTTP checks in CI. Nuxt 4.4.2 passes the same checks locally on Linux x86_64 with Node 24.19.0, including diagnostics, Scala source maps, relink reloads, and production bundling. Package-level checks cover Node 22.18.0 and 24. Other Nuxt versions and Nix/NixOS need separate validation; see [compatibility](/reference/compatibility).

## Describe the application outputs

Create `h34s.config.mjs` beside `package.json`:

```js
import { defineConfig } from '@yuri4n/h34s-nuxt/build'

export default defineConfig({
  modules: [
    {
      project: 'server',
      output: 'server/.scala',
      entries: ['notes-get.js', 'notes-post.js'],
    },
  ],
})
```

`project` is the sbt project ID; omit it for the root sbt project. `output` is the generated directory relative to the application root. `entries` lists the route files linking must produce. Add another module and output directory for an independent Kyo application if needed.

Configure `fastLinkJS` and `fullLinkJS` in your own `build.sbt` to write ES modules into that same output directory, and enable development source maps. The package invokes the configured sbt tasks; it does not rewrite Scala build settings or install Java/sbt. Keep only generated code in output directories: production linking removes their previous contents.

Enable the Nuxt module:

```ts
export default defineNuxtConfig({
  modules: ['@yuri4n/h34s-nuxt'],
})
```

It reads the same config and supplies the development hooks and runtime diagnostics plugin. Remove copied versions of those hooks and the `h34s-development` plugin when switching to the module.

## Run one build pipeline

Add application scripts:

```json
{
  "scripts": {
    "scala:fast": "h34s-scala dev",
    "scala:watch": "h34s-scala watch",
    "scala:full": "h34s-scala build",
    "dev": "node --enable-source-maps node_modules/nuxt/bin/nuxt.mjs dev",
    "dev:scala": "pnpm run scala:fast && pnpm run dev",
    "build": "pnpm run scala:full && nuxt build"
  }
}
```

Run `pnpm dev:scala` to link and start Nuxt; keep `pnpm scala:watch` in a second terminal while editing. The watcher runs continuous Scala linking; Nitro watches generated output and restarts its worker after changes. The [debugging guide](/guide/debugging) explains error details and Scala source locations.

`pnpm build` clears old output, runs production linking, checks every configured entry, and only then builds Nuxt. A failed link or missing entry stops the build. Keep the explicit link-before-Nuxt ordering: the Nuxt module does not production-link automatically.

The CLI supports `--root <directory>` and `--config <file>`. For an alternate config in Nuxt, use `modules: [['@yuri4n/h34s-nuxt', { configFile: 'custom.mjs' }]]`; keep both tools pointed at the same application config. sbt must be available on `PATH`.

Route mounts remain application-owned until route generation is implemented. Scala dependencies stay in Maven, so installing this npm package does not add ZIO, Kyo, or Schema to the Scala classpath. See [adoption](/guide/adoption) for project layouts and [compatibility](/reference/compatibility) for the toolchain. Windows and Nix/NixOS remain unverified.
