Schemas are optional. `NativeConverter` is the type class every h34s API asks for, and `derives NativeConverter` is a complete path. Add a schema when you want validation in the model, or JSON and YAML from the same definition:

```scala
final case class Greeting(message: String) derives Schema, NativeSchema
```

One derivation gives the native value h34s sends and reads, JSON text, YAML text (Kyo only), and validation on every body read.

> **Status.** This page describes both bridges in `0.2.0-alpha.1`.

## Choose a bridge

|            | Kyo                                           | ZIO                                                             |
| ---------- | --------------------------------------------- | --------------------------------------------------------------- |
| Module     | `native-converter-kyo-schema-ext`             | `native-converter-zio-schema-ext`                               |
| Derive     | `derives Schema, NativeSchema`                | `derives Schema, NativeSchema` with `import zio.schema.derived` |
| JSON       | kyo-schema-json `Json.encode` / `Json.decode` | zio-schema-json                                                 |
| YAML       | kyo-schema-yaml                               | not on Scala.js: zio-json-yaml is JVM-only                      |
| Validation | `Schema[A].check(...)`                        | `Validation` in the schema                                      |
| Messages   | yours                                         | built from the rule and its bounds                              |

Neither bridge installs a blanket instance, and a type can keep its own `NativeConverter`. Add kyo-schema-json or kyo-schema-yaml yourself when you need text formats.

## Kyo

For a model with checks, declare the schema in the companion and derive only `NativeSchema` (kyo-schema has no check annotations). The demo's `Greetings.scala`:

```scala
final case class GreetingRequest(name: String) derives NativeSchema

object GreetingRequest:
    given Schema[GreetingRequest] = Schema[GreetingRequest]
      .check(_.name)(_.trim.nonEmpty, "must not be blank")
      .checkMaxLength(_.name)(80)

final case class Greeting(message: String) derives Schema, NativeSchema
```

`request.body.json[GreetingRequest]` then answers a blank name with a 422 and `{"errors":[{"message":"must not be blank","path":"name"}]}`, and an 81-character name with `length must be <= 80`.

The same schema gives text formats:

```scala
val json = Json.encode(greeting)
val yaml = summon[Schema[Greeting]].encodeString[Yaml](greeting)
```

Wire shapes match `JSON.parse(Json.encode(x))`: `None` is an absent key; enum and sealed-trait cases are single-key objects such as `{"Red":{}}` (or `{"type":...}` with `@discriminator`); `Map[String, A]` is an object, other maps are `{"key","value"}` arrays; big numbers are strings (decoding rejects more than 1000 characters or an exponent beyond +/-10000 with a generic 422); `Instant` and `Duration` are ISO strings; bytes are base64; a `Long` decodes only up to 2^53 - 1.

Only the root schema's checks run, so put checks on the root with focus paths such as `_.customer.name`. A wrong shape gives one generic entry. A throwing transform is a defect (500).

## ZIO

The demo's `Notes.scala` trims and checks the text in the schema:

```scala
final case class NoteView(id: Int, text: String) derives Schema, NativeSchema

final case class CreateNote(text: String) derives NativeSchema

object CreateNote:
    /** Trims the text, then requires 1-2000 characters. The native converter uses this schema. */
    given Schema[CreateNote] =
      given Schema[String] = Schema.Primitive(StandardType.StringType)
        .transform(_.trim, identity)
        .validation(Validation.minLength(1) && Validation.maxLength(2000))
      DeriveSchema.gen[CreateNote]
```

A blank text gets `{"errors":[{"message":"must have at least 1 character","path":"text"}]}`. ZIO Schema's own messages quote the input, so the bridge writes messages from the rule and its bounds, with paths such as `members[1].name`.

The ZIO bridge supports strings, booleans, `Int`, `Double`, records, options, sequences, lazy and transformed schemas. Enums, sealed traits, maps, sets and tuples fail with `UnsupportedSchema` when the converter is created.

## Secrets

Each bridge provides a `Schema[Secret]` (a string on the wire). Import `dev.yuri4n.exts.ntcvkyoschema.secretSchema` or `dev.yuri4n.exts.ntcvzioschema.secretSchema` where you derive a schema that holds a `Secret`, such as a config model. Errors never contain the value; JSON or YAML written with this schema does.

## TypeScript types

Both bridges' converters describe the TypeScript type of what they write, so a route that returns a schema type gets a typed `$fetch` ([routes and typed $fetch](/guide/routes)). Records keep their wire names, optional values are `T | null` (Kyo: the key may also be absent), collections are arrays, string-keyed maps are `Record<string, T>`, and Kyo sealed traits and enums are one-key objects or `@discriminator` objects.

Kyo's `Structure` does not show fluent changes such as `Schema.rename`, `drop`, `add` or omit policies, also in a nested type's schema. The Kyo bridge therefore checks its type against its encoder with sample values of every shape and gives `unknown` when an output does not match. Prefer annotations (`@rename`, `@discriminator`) for types you send to TypeScript clients.

## Request errors

| Problem                               | Status                                |
| ------------------------------------- | ------------------------------------- |
| Invalid JSON                          | 400                                   |
| Wrong shape                           | 422, one generic entry                |
| Failed checks                         | 422, one entry per check, with `path` |
| Exception in a transform or converter | 500, opaque                           |

Do not turn every `Throwable` into a `SafeError`: programming errors would look like input problems.

Tested: the Kyo bridge's wire equality with kyo-schema-json, strict decoding, messages and paths, no JSON text round trip, JSON/YAML round trips, and TypeScript types checked against the encoder (29 tests); the ZIO bridge's shapes, entries and TypeScript types (22 tests); 400/422 over h3 in both runtimes.
