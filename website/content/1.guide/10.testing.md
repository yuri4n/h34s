A handler is a plain function from `Request` to a program. Test it like any function: build a fake request, run the program with an empty response head, and check the body and the head.

> **Status.** `Request.fake` is part of `0.2.0-SNAPSHOT` (unreleased).

## Keep handlers as values

Define the function as a value and pass it to `AppHandler.define` separately, as the demo's `NotesHandler` does. Put services behind traits so a test can supply an in-memory one.

## Build a fake request

```scala
Request.fake(
  method = "POST",
  headers = Map("content-type" -> "application/json"),
  routerParams = Map("id" -> "7"),
  body = Some("""{"text":"hello"}"""),
)
```

`path`, `query`, `cookies`, `development`, `debug` and `bodyLimit` are available too. Body reads follow the real rules. A fake request has no Nitro record, so `RuntimeConfig.get(request)` fails with `ConfigError`: read configuration in `AppHandler` and pass values to handlers as services.

## Kyo

From the core's own tests:

```scala
val handler: Request => Greeting < HandlerEffects = request =>
  for
    first <- request.body.json[Input]
    _     <- Response.status(Status.Created)
  yield Greeting(first.name)

val request = Request.fake(method = "POST", body = Some("{\"name\":\"Scala\"}"))
val program = Scope.run(Var.runTuple(ResponseHead.empty)(handler(request)))
// (ResponseHead, Greeting) < (Async & Abort[Throwable])
```

Run `program` with your Kyo test setup; the h34s munit suites use `Fiber.Unsafe.init(Abort.run[Throwable](program)).toFuture()` under `AllowUnsafe.embrace.danger`. Provide services with `Env.run` before `Var.runTuple`. The head contains only what your program set: handler defaults are added later by the core.

## ZIO

From the demo's `NotesHandlerSpec`, with an in-memory `Notes`:

```scala
private def run[A](program: ZIO[HandlerEnv & Notes, Throwable, A]): Task[(ResponseHead, A, List[String])] =
  for
    created <- Ref.make(List.empty[String])
    result <- ZIO.scoped(ZIO.stateful[Scope](ResponseHead.empty)(
      program.zip(Response.head).provideSomeEnvironment[ZState[ResponseHead] & Scope](_.add[Notes](InMemoryNotes(created))),
    ))
    texts <- created.get
  yield (result._2, result._1, texts)

test("create rejects invalid input before the service runs") {
  for result <- run(NotesHandler.create(post("{\"text\":\"   \"}"))).either
  yield assertTrue(result == Left(InvalidInput(List(ErrorEntry("must have at least 1 character", Some("text"))))))
}
```

## Pin the wire contract

- **Shapes:** compare `js.JSON.stringify(summon[NativeConverter[A]].toNative(value))` with what your TypeScript types expect.
- **Errors:** assert exact `InvalidInput` entries; they are your 422 contract.
- **Head:** assert `head.status` and headers from the run.
- **Envelope:** `{"data": ...}`, `{"errors": [...]}` and 204 come from the core and its tests. Check them end to end with an HTTP request against a running server.

Without the Nitro plugin, `Shared` and `ZShared` register nothing; call `close` at the end of a test.

The h34s suites themselves (245 Scala tests on this branch, plus the npm package's Node tests) cover request snapshots, body limits, envelopes, the failure rule, diagnostics, finalizers, disconnects, streaming, shared resources, configuration, storage and both schema bridges.
