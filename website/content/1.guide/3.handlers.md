`ZHandler.define` turns a ZIO program into an h3 handler. It supplies the HTTP request context, scopes execution, converts the result to a native JavaScript value, and hides runtime and Promise handling.

Application services fit around that boundary through ordinary ZIO provisioning. The example calls its composition point `AppHandler`.

## Ask for an application service

The Notes GET handler is a small ZIO program:

```scala
import dev.yuri4n.svr.app.AppHandler
import dev.yuri4n.svr.notes.Notes
import zio.ZIO

import scala.scalajs.js.annotation.JSExportTopLevel

@JSExportTopLevel("default", "notes-get")
val listNotes = AppHandler.define:
    ZIO.serviceWithZIO[Notes](_.list)
```

`Notes` is an application service. The handler asks for it from the ZIO environment; it does not create a connection or execute a runtime. This code comes from `scala-modules/svr/src/main/scala/dev/yuri4n/svr/handlers/NotesHandler.scala`.

## Define the data you exchange

The application models derive `NativeConverter`:

```scala
import org.getshaka.nativeconverter.NativeConverter
import zio.Task

final case class Note(id: Int, text: String) derives NativeConverter
final case class CreateNote(text: String) derives NativeConverter

trait Notes:
    def create(text: String): Task[Note]
    def list: Task[List[Note]]
```

The default native representation follows these fields. The handler boundary converts the Scala result directly to a JavaScript value. HTTP serialization is a separate transport step.

## Choose your decoding approach

`NativeConverter` alone is a complete supported integration. Use
`ZHandler.readBody[A]` to decode a request with the converter for `A`; no
schema library is required. Keep model validation in the application when
using this path. A converter defines a representation, not automatically
all of a model's domain constraints.

The current Notes POST implementation has explicit null and text-length
guards because NativeConverter 0.9 accepts missing or null `String`
fields. Those guards describe a limitation of the current example, not
the intended schema-based developer experience.

An **optional ZIO Schema bridge is available in a
[separate draft PR](https://github.com/yuri4n/h34s/pull/6)**. It defines
decoding and constraints once on the model schema, then requests a
validated value with `ZHandler.readBodyWithSchema[CreateNote]`.
ZIO Schema and Kyo Schema integrations should remain separate optional
modules, alongside native-value, JSON, and YAML codec bridges. They must
not add a schema dependency to the NativeConverter-only path.

The current documentation branch does not yet include that PR.
See [status](/reference/status) for the supported boundary. The Notes
service and `AppHandler` environment composition are the same regardless
of which decoding approach the application chooses.

## Choose what a client may see

| Failure                                   | Response                                                    |
| ----------------------------------------- | ----------------------------------------------------------- |
| `SafeError`                               | Its approved `message` and `status`; status defaults to 400 |
| `ZHandler.failWith(status, message, ...)` | The explicit status and error messages                      |
| Unexpected exception or defect            | HTTP 500 with `Internal server error`                       |

Safe error responses use an `errors` array:

```json
{
  "errors": ["Text must contain between 1 and 2000 characters"]
}
```

Keep internal exception details out of safe error messages. Nuxt development mode adds the original cause and trace for unexpected failures; production responses stay opaque. See [debugging](/guide/debugging).

## Compose services once in application code

The example's `AppHandler` provides the application environment before calling the library boundary:

```scala
import dev.yuri4n.exts.h3.CommonEvHandler
import dev.yuri4n.exts.ntcvzio.given
import dev.yuri4n.exts.zioh3.{SH3Event, ZHandler}
import dev.yuri4n.svr.notes.Notes
import org.getshaka.nativeconverter.NativeConverter
import zio.{Scope, ZIO}

object AppHandler:
    def define[A: NativeConverter](
        program: ZIO[SH3Event & Scope & Notes, Throwable, A],
    ): CommonEvHandler =
      ZHandler.define(program.provideSomeLayer[SH3Event & Scope](Services.layer))

    def define(
        program: ZIO[SH3Event & Scope & Notes, Throwable, Unit],
    ): CommonEvHandler = define[Unit](program)
```

`Services` lives in the same application package. It composes database configuration, a scoped connection, and `NotesLive`. Endpoint code can then focus on the request and service call.

This is application policy, not a mandatory library container. Adapt the environment to your own services with ordinary `ZLayer`, `provide`, and scoping operations. The example opens one database connection per request; reusing its layer value does not create an application-wide pool.
