`ZHandler.define` turns a ZIO program into an h3 handler. It supplies the HTTP request context, scopes execution, converts the result to a native JavaScript value, and hides runtime and Promise handling.

Define and provide your application services with ordinary ZIO provisioning before passing the program to `ZHandler.define`. If several endpoints share this setup, write a helper in your application. The example names that helper `AppHandler`; it is optional application code, not an exported h34s API.

For Kyo programs, use the independent [Kyo handler API](/guide/kyo). Both integrations use native h3 bindings and leave application services in your application modules.

## Ask for an application service

Request your service from the ZIO environment. This Notes GET example uses the application-defined `AppHandler` shown [below](#compose-services-once-in-application-code):

```scala
import dev.yuri4n.svr.app.AppHandler
import dev.yuri4n.svr.notes.Notes
import zio.ZIO

import scala.scalajs.js.annotation.JSExportTopLevel

@JSExportTopLevel("default", "notes-get")
val listNotes = AppHandler.define:
    ZIO.serviceWithZIO[Notes](_.list)
```

`Notes` is an application service. The handler asks for it from the ZIO environment; it does not create a connection or execute a runtime. This code comes from `examples/nuxt/scala/zio/src/main/scala/dev/yuri4n/svr/handlers/NotesHandler.scala`.

## Define the data you exchange

Define your request and response models in your application. In this example, derive `NativeConverter` for the response and use the optional ZIO Schema integration to define request decoding and validation:

```scala
import org.getshaka.nativeconverter.NativeConverter
import zio.Task
import zio.schema.{DeriveSchema, Schema, StandardType}
import zio.schema.validation.Validation

final case class Note(id: Int, text: String) derives NativeConverter
final case class CreateNote(text: String)

object CreateNote:
    given Schema[CreateNote] =
      given Schema[String] = Schema.Primitive(StandardType.StringType)
        .transform(_.trim, identity)
        .validation(Validation.minLength(1) && Validation.maxLength(2000))
      DeriveSchema.gen[CreateNote]

trait Notes:
    def create(text: String): Task[Note]
    def list: Task[List[Note]]
```

The default native representation follows these fields. The handler boundary converts the Scala result directly to a JavaScript value. HTTP serialization is a separate transport step.

## Choose your decoding approach

`NativeConverter` alone is a complete supported integration. Use
`ZHandler.readBody[A]` to decode a request with the converter for `A`; no
schema library is required. Keep model validation in the application when
using this path. A converter defines a representation, not automatically
all of a model's domain constraints.

The **optional ZIO Schema bridge is integrated** in `nativeConverterZIOSchemaExt`
and `zioH3SchemaExt`. The Notes model above trims text and checks its length;
the handler requests the validated value without repeating those rules:

```scala
import dev.yuri4n.exts.zioh3schema.readBodyWithSchema

val createNote = AppHandler.define:
    for
      input <- ZHandler.readBodyWithSchema[CreateNote]
      note <- ZIO.serviceWithZIO[Notes](_.create(input.text))
      _ <- ZHandler.setResponseStatus(201)
    yield note
```

Invalid input returns HTTP 422 with `Request body does not match schema`.
Plain `readBody[A]` remains available without a schema dependency;
NativeConverter 0.9 accepts missing or null `String` fields, so that path
needs application validation when those values are invalid. Kyo Schema
and further JSON/YAML codec bridges remain separate work.

The [schema guide](https://github.com/yuri4n/h34s/blob/v0.1.0-alpha.1/docs/schema.md)
records supported forms and conversion rules. The Notes service and
`AppHandler` environment composition stay the same for either approach.

## Choose what a client may see

| Failure                                   | Response                                                    |
| ----------------------------------------- | ----------------------------------------------------------- |
| `SafeError`                               | Its approved `message` and `status`; status defaults to 400 |
| `ZHandler.failWith(status, message, ...)` | The explicit status and error messages                      |
| Unexpected exception or defect            | HTTP 500 with `Internal server error`                       |

Safe error responses use an `errors` array:

```json
{
  "errors": ["Text must contain between 1 and 2000 characters"]
}
```

Keep internal exception details out of safe error messages. Nuxt development mode adds the original cause and trace for unexpected failures; production responses stay opaque. See [debugging](/guide/debugging).

## Compose services once in application code

Create a helper like the example's `AppHandler` to provide shared service layers before calling `ZHandler.define`. Choose the name and environment for your application:

```scala
import dev.yuri4n.exts.h3.CommonEvHandler
import dev.yuri4n.exts.ntcvzio.given
import dev.yuri4n.exts.zioh3.{SH3Event, ZHandler}
import dev.yuri4n.svr.notes.Notes
import org.getshaka.nativeconverter.NativeConverter
import zio.{Scope, ZIO}

object AppHandler:
    def define[A: NativeConverter](
        program: ZIO[SH3Event & Scope & Notes, Throwable, A],
    ): CommonEvHandler =
      ZHandler.define(program.provideSomeLayer[SH3Event & Scope](Services.layer))

    def define(
        program: ZIO[SH3Event & Scope & Notes, Throwable, Unit],
    ): CommonEvHandler = define[Unit](program)
```

Define `Services.layer` in your application package. In the Notes example, compose database configuration, a scoped connection, and `NotesLive` there; the [database guide](/guide/database#keep-sql-in-an-application-service) shows that layer. Endpoint code can then request `Notes` without repeating its construction.

Use ordinary `ZLayer`, `provide`, and scoping operations to adapt this helper to your services, or provide them directly when calling `ZHandler.define`. h34s does not create `AppHandler`, `Services`, or a database layer for you. The example opens one database connection per request; reusing its layer value does not create an application-wide pool.

Continue with [database services](/guide/database), [streaming](/guide/streaming), or the [architecture reference](/reference/architecture).
