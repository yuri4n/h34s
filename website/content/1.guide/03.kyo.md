Kyo is the h34s core. `KHandler.define` turns a Kyo function into an h3 handler. It takes an immutable snapshot of the request, runs your program once per request, owns its scope and cancellation, and writes the response once. A Kyo application never depends on ZIO.

> **Status.** This page describes `0.2.0-alpha.1`. The older `0.1.0-alpha.1` Kyo API is different; see the [migration guide](/reference/migration).

Add `"dev.yuri4n" %%% "kyo-h3-ext"`, build with Scala 3.9.0 and JDK 25, and import `dev.yuri4n.exts.kyoh3.*` and `kyo.*`.

## Write a handler

A handler is a function from `Request` to the body:

```scala
import dev.yuri4n.exts.kyoh3.*
import kyo.*
import org.getshaka.nativeconverter.NativeConverter

import scala.scalajs.js.annotation.JSExportTopLevel

final case class Greeting(message: String) derives NativeConverter

@JSExportTopLevel("default", "hello-get")
val hello: EventHandler = KHandler.define: request =>
    Greeting(s"Hello from ${request.path}")
```

The response is `200` with `{"data":{"message":"Hello from ..."}}`. Mount the export with a one-line route file, as in [adoption paths](/guide/adoption#write-mount-and-run-a-handler).

## Read the request

`Request` is taken once, when the handler starts:

| Member                                          | Value                                                   |
| ----------------------------------------------- | ------------------------------------------------------- |
| `method`, `path`                                | Upper-case method; path and query                       |
| `header(name)`, `headers`, `headerValues(name)` | Case-insensitive headers                                |
| `query`, `queryAll`                             | First value, or all values, per key                     |
| `routerParam(name)`, `routerParams`             | Decoded router parameters                               |
| `cookie(name)`, `cookies`                       | Parsed cookies                                          |
| `bearerToken`                                   | The token of exactly one `Authorization: Bearer` header |
| `development`, `debug`                          | Set only by the h34s Nitro plugin                       |

`request.param(name)` fails with a 400 when a router parameter is missing.

Read the body once with `request.body.json[A]` or `request.body.text()`:

<!-- claude 2026-10-19: changed: the 415 and 413 rows (a body without a content type is rejected after the read, issue #41) -->

| Situation                                                                                                                | Result                                     |
| ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------ |
| Content type not JSON, or absent while the request has a body (absent is accepted with `requireJsonContentType = false`) | 415                                        |
| Body above the limit (1 MiB by default); a body without a content type is read up to the limit before the 415            | 413, without buffering more than the limit |
| Invalid JSON                                                                                                             | 400                                        |
| Wrong shape for the converter                                                                                            | 422, one generic entry                     |
| A schema rejects the value                                                                                               | 422, one entry per check, with `path`      |
| Any other converter exception                                                                                            | Opaque 500                                 |

<!-- claude 2026-10-19: changed: the strict content type is the default; a request without a body needs none (issue #41) -->

An absent or empty body, with a JSON content type or none, decodes like JSON `null`: a model answers 422, `json[Option[A]]` gives `None`. `text()` never checks the content type.

<!-- claude 2026-10-19: changed: the opt-out rule, as in docs/kyo.md (issue #41) -->

A browser sends no content type for a cross-site `fetch` with a byte body or for `sendBeacon`, without a CORS preflight. That is why `json[A]` answers 415 for a body without a content type by default. `$fetch` with an object body and `curl --json` send `application/json`. For cookie-authenticated routes that change state, keep cookies `SameSite=Lax` (the default) or `Strict`, keep `requireJsonContentType` on (turn it off only for a handler whose clients cannot send a content type and that does not change state for a cookie-authenticated user), and check `sec-fetch-site` or `origin`.

## Return a body

| You return                       | Response                                                         |
| -------------------------------- | ---------------------------------------------------------------- |
| A value with a `NativeConverter` | 200 (or your status) with `{"data": value}`                      |
| `Unit`                           | 204, no body                                                     |
| A `kyo.Stream[String, S]`        | Strings written as UTF-8 text; see [streaming](/guide/streaming) |

## Set status, headers and cookies

The response head is local state, a `Var[ResponseHead]`. h34s writes it once, after your program and its finalizers finish:

```scala
val created: EventHandler = KHandler.define: request =>
    for
      input <- request.body.json[GreetingRequest]
      _     <- Response.status(Status.Created)
      _     <- Response.header("x-request-id", "abc", OnFailure.Keep)
      _     <- Response.cookie(SetCookie("session", "abc", maxAge = Some(3600)))
    yield Greeting(s"Hello, ${input.name}!")
```

`Response` also has `appendHeader`, `deleteCookie(name, path, domain, secure, onFailure)`, `redirect(location, status)` and `head`. Cookies default to `Path=/`, `HttpOnly`, `Secure` and `SameSite=Lax`; a deletion sends `Secure` by default, which a `__Host-` cookie needs. An invalid header or cookie name is a programming error: the handler fails when the operation runs and answers 500.

## Fail safely

Only a `SafeError` that you fail with through `Abort.fail` reaches the client:

```scala
final case class NoteNotFound(id: String) extends SafeError:
    def message: String     = "Note not found"
    override def status: Int = 404
```

| Failure                                                   | Status                        | Body                                               |
| --------------------------------------------------------- | ----------------------------- | -------------------------------------------------- |
| `Abort.fail(safeError)`                                   | its `status` (400 by default) | `{"errors":[{"message":"..."}]}`                   |
| `KHandler.failWith(status, message)` (`Abort[HttpError]`) | `status`                      | same shape                                         |
| `InvalidInput` from a body read                           | 422                           | entries with `path`, never input values            |
| Anything else, including a thrown `SafeError`             | 500                           | `{"errors":[{"message":"Internal server error"}]}` |

`HttpError` is a ready-made `SafeError` with helpers such as `HttpError.unauthorized("Sign in").header("WWW-Authenticate", "Bearer")`.

On failure the status always comes from the error, so a 2xx never leaks. Handler defaults, entries marked `OnFailure.Keep` and the error's headers survive; everything else your program set is discarded. Never put secrets or input values in a `SafeError` message.

## Choose the wire format

Pass `HandlerOptions` to `KHandler.define(options)(program)`:

<!-- claude 2026-10-19: changed: the `requireJsonContentType` row (default `true`, issue #41) -->

| Option                   | Default                   | Alternative                                                                                                                      |
| ------------------------ | ------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `success`                | `{"data": value}`         | `SuccessEnvelope.Raw`: no envelope; a string as `text/plain; charset=utf-8`, other values as JSON, unless you set a content type |
| `errors`                 | always `{"errors":[...]}` | `ErrorEnvelope.SingleOrList`: `{"error":{...}}` for one entry                                                                    |
| `defaults`               | none                      | for example `ResponseHead.noStore`, on success and failure                                                                       |
| `bodyLimit`              | 1 MiB                     | any `BodyLimit(bytes)`                                                                                                           |
| `requireJsonContentType` | `true`                    | `false`: accept a JSON body without a content type (`true` answers 415)                                                          |

## Wire services in your AppHandler

Write one wiring point that provides your services. The demo's (`AppHandler` is application code, not an h34s export):

```scala
object AppHandler:
    private val options = HandlerOptions(defaults = ResponseHead.noStore)

    def define[B: ResponseBody](
        program: Request => B < (HandlerEffects & Env[Greetings]),
    )(using Frame): EventHandler =
      KHandler.define(options)(request => Services.greetings.get.map(greetings => Env.run(greetings)(program(request))))
```

`Services.greetings` is a [`Shared`](/guide/lifetimes) service built from the startup runtime config.

Endpoints ask for the service:

```scala
@JSExportTopLevel("default", "kyo-greeting-post")
val personalizedGreeting: EventHandler = AppHandler.define: request =>
    for
      input    <- request.body.json[GreetingRequest]
      greeting <- Env.use[Greetings](_.greet(input.name))
    yield greeting
```

`HandlerEffects` is `Async & Scope & Abort[Throwable] & Var[ResponseHead]`. Resolve every other effect before `KHandler.define`. `Env.run` provides values; it owns no resources. Use [`Shared`](/guide/lifetimes) for a pool and [`RuntimeConfig`](/guide/configuration) for settings.

## Kyo details to keep in mind

- **`Abort.run[Throwable]` catches thrown exceptions too.** Recover narrower types in your own code. h34s itself keeps thrown exceptions as defects.
- **`Abort.recover` does not roll back `Var`.** A status set before a recovered failure stays set.
- **`Var` needs an isolate across forks.** Call `Response.*` in the request fiber, not inside `Fiber.init` or `Async.race`.
- **`Scope` finalizer errors are logged** and do not change the response.
- **`Async.uninterruptible` does not make the request wait.** Use `KHandler.uninterruptible(step)` in a handler ([lifetimes](/guide/lifetimes)).

## Choose locale data

Kyo brings a full currency database that adds tens of MB of JavaScript. If you do not format currencies, exclude it in `build.sbt`, as the demo does:

```scala
excludeDependencies += ExclusionRule("io.github.cquiroz", "locales-full-currencies-db_sjs1_3")
```

## Run the demo's routes

With the demo running ([getting started](/guide/getting-started)), `GET /api/kyo/greeting` returns `{"data":{"message":"Hello, Kyo!"}}`, and a POST with a blank name returns a 422 with `{"errors":[{"message":"must not be blank","path":"name"}]}`. These responses were checked in a production build of the demo, under `nuxt dev`, and over a plain h3 server. `NUXT_GREETING_SALUTATION=Hi` changes the salutation.
