**h34s is an unpublished ZIO development slice.** It is available as source in a private repository. There are no released artifact coordinates, stable public package names, or project generator yet.

## Implemented in the example

| Capability              | Current scope                                                                  |
| ----------------------- | ------------------------------------------------------------------------------ |
| `ZHandler.define`       | Request-scoped ZIO execution with native-value conversion                      |
| Application services    | Application-owned `AppHandler` and ordinary `ZLayer` composition               |
| Error responses         | Approved safe messages; opaque unexpected failures outside development         |
| Development diagnostics | Original cause and ZIO trace, controlled by Nuxt development mode              |
| Source maps             | Scala.js maps composed through Nitro with local Scala source content           |
| Streaming               | Pull-driven adapter for direct Node HTTP, with cancellation and scoped cleanup |
| PostgreSQL example      | Skunk insert/read, input validation, and one connection per request            |

The [guides](/guide/getting-started) describe these paths using the existing application source.

## Validation performed

The prepared cloud checkout has exercised:

- 31 Scala handler and stream tests, including conversion, error boundaries, provisioning, and cleanup.
- Six source-map checks and application development linking.
- Nuxt startup and direct HTTP streaming.
- A real PostgreSQL 16 insert/read using SCRAM authentication.
- Safe 422 responses for blank, null, missing, and incorrectly typed input.
- A real query failure returning development diagnostics with a Scala source frame.
- Connection cleanup after successful requests, input failures, and query failure.

Production error suppression and Nitro's production replacement of the development flag were checked separately. Those checks do not establish a complete production application build or deployment.

The library's response-close tests use real h3 with mocked Node responses. An actual client-abort integration check remains to be added. Interactive breakpoint stepping is also unverified, although source-map stack remapping and source inclusion have been checked.

## Limits to account for now

- **Source adoption:** the prepared checkout is exercised; a fresh machine and external Nuxt/Scala.js consumers still need dedicated validation.
- **Streaming:** the scoped adapter supports direct Node HTTP. Nitro's no-socket local-fetch path is rejected, and other deployment adapters need their own lifecycle checks.
- **Buffering:** one upstream chunk is pulled at a time, but h3 does not await Node response `drain`. There is no established end-to-end HTTP memory bound.
- **Database lifetime:** the example opens one connection per request. It does not provide an application-wide pool, transaction guide, or migration system.
- **Production output:** only development linking is configured to emit into `server/.scala`. The historical production script is not a verified packaging path.
- **Type generation:** `scala:types` invokes ScalablyTyped, which generates Scala facades from TypeScript. Scala-to-TypeScript wire generation is not wired up.

## Planned work

The agreed direction includes these separate implementation slices:

1. Add optional schema bridges for model-owned decoding and validation, while preserving NativeConverter-only use. ZIO Schema comes first; Kyo Schema and additional JSON/YAML codecs need separate validation.
2. Publish independently consumable native and ZIO modules, with a compatibility policy and fresh-consumer checks.
3. Automate route discovery, mounting, and TypeScript wire-type generation.
4. Add a first-class Kyo API using its own runtime and shared transport behavior tests.
5. Add application-scoped Skunk pooling with explicit startup, shutdown, and request/stream leases.
6. Validate production linking and Nuxt packaging, then add the planned Nix and sbt-native-packager paths.
7. Investigate compiler-derived type information, symbol navigation, and editable examples for documentation.

The current documentation presents static source examples. It does not provide semantic Scala hovers, an editable compiler, or a browser-hosted Nitro/PostgreSQL playground. Those features require separate tooling and validation.

See [architecture](/reference/architecture) for the boundaries behind this roadmap and [adoption](/guide/adoption) for the three intended ways to use h34s.
