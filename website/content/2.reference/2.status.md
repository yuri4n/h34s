## What 0.2.0-alpha.1 provides

| Capability                                                             | Kyo                             | ZIO                                      |
| ---------------------------------------------------------------------- | ------------------------------- | ---------------------------------------- |
| Handlers as `Request => body` functions                                | `KHandler.define`               | `ZHandler.define`                        |
| Response head as local state, written once                             | `Var[ResponseHead]`             | `ZState[ResponseHead]`                   |
| Wire format `{data}` / `{errors:[{message,path}]}` / 204, configurable | `HandlerOptions`                | `HandlerOptions`                         |
| Bounded body reads with 400/413/415/422                                | `request.body.json`, `text`     | same                                     |
| Safe errors, opaque 500s, development and debug diagnostics            | yes                             | yes, with `Cause.prettyPrint`            |
| Runtime config from Scala, `Secret`                                    | `RuntimeConfig`                 | `ZRuntimeConfig`                         |
| Application-scoped resources released on Nitro close                   | `Shared`                        | `ZShared`                                |
| Streams with cancellation that waits for cleanup                       | `kyo.Stream`                    | `ZStream`                                |
| Nitro storage                                                          | `KHubKv.mount`                  | `ZHubKv.mount`                           |
| One schema for native values, JSON, YAML and validation                | Kyo `NativeSchema`              | ZIO `NativeSchema` (no YAML on Scala.js) |
| Testing without h3                                                     | `Request.fake` + `Var.runTuple` | `Request.fake` + `ZIO.stateful`          |
| Routes declared in Scala, typed `$fetch` from generated declarations   | `.at(Route...)`                 | `.at(Route...)`                          |

## Verified, and how

On macOS x86_64 with JDK 25 and Node 24.19.0: 276 Scala tests across the native layer, the Kyo core, the ZIO adapter, both schema bridges, storage and the ZIO demo; the npm package's Node tests; fresh Maven consumers for Kyo, ZIO and both schema bridges (Kyo consumers resolve no ZIO); a production build of the demo serving the Kyo and ZIO routes, debug mode with `NUXT_H34S_DEBUG=true`, and releasing the shared pool on `SIGTERM`; and `nuxt dev` with development diagnostics and Kyo stacks mapped to Scala sources. For the generated routes, the demo has no route files: a production build served the Kyo and ZIO routes from the manifests, a type check proved typed `$fetch` from the declarations, and the packed module mounted a route added while `nuxt dev` ran. Details are in [compatibility](/reference/compatibility).

## Not verified yet

- Relinking the real demo under `nuxt dev`, and breakpoint stepping (diagnostics and source maps under `nuxt dev` were checked).
- The ZIO Notes demo against a real PostgreSQL.
- kyo-sql at runtime: the [database guide](/guide/database) code compiles but has never run.
- NuxtHub KV as a Nitro storage mount.
- Linux, Windows, Nix, and non-Node Nitro presets.

## Limits to plan around

- **Generated types:** response bodies only. Request bodies and query strings have no generated type, and a converter that does not describe itself gives `unknown`.
- **Streaming:** direct Node HTTP only; no end-to-end memory bound because h3 does not wait for `drain`.
- **ZIO Schema:** no enums, sealed traits or maps yet; no YAML on Scala.js.
- **Kyo finalizers:** failures are logged and do not change the response.
- **Locale data:** Kyo brings a large currency database; exclude it in applications that do not need it.
- **Build memory:** the demo's `nuxt build` needed `NODE_OPTIONS=--max-old-space-size=8192`.
