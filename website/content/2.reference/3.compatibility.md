A compatibility profile is a set of versions tested together, on a stated platform, with stated evidence. This page keeps three kinds apart: **locally verified** (one machine), **CI-validated** (a linked workflow run), and **untested** (no evidence; do not rely on it). Listing a library here does not make it a dependency of your application.

#### Release workflows

Both tags point at `433ac9d`, and the npm release finished before the Maven release started. Both ran on Linux x86_64.

- The [npm release workflow](https://github.com/yuri4n/h34s/actions/runs/39144809255) for `npm-v0.2.0-alpha.1` ran the Node 22.18.0 and 24 package checks and the Nuxt 4.3.1 development and production HTTP checks with the packed module. It then published the package, downloaded it with registry authentication, required the download to be byte-identical to the tested archive, and checked an offline install. The [npm release](https://github.com/yuri4n/h34s/releases/tag/npm-v0.2.0-alpha.1) attaches the archive and `registry.json`.
- The [Maven release workflow](https://github.com/yuri4n/h34s/actions/runs/39145732257) for `v0.2.0-alpha.1` ran every test suite, production linking, the release metadata checks and the four consumers from a staged repository. It then published the nine artifacts, and `check-consumers.mjs --published` resolved the Kyo, ZIO, Kyo Schema and ZIO Schema consumers from GitHub Packages; each one served real h3 requests. The [prerelease](https://github.com/yuri4n/h34s/releases/tag/v0.2.0-alpha.1) was created after that check passed.

### Known gaps

- zio-json-yaml has no Scala.js artifact, so ZIO models have no YAML codec in Nitro.
- The ZIO schema bridge does not support enums, sealed traits or maps yet.
- Kyo `Scope` finalizer failures are logged; ZIO finalizer defects turn a value response into a 500.
- The demo's `nuxt build` needs a larger Node heap (`--max-old-space-size=8192`).

## Nix

No Nix profile exists yet. A future profile must record its lock revision, run the same sbt/pnpm pipeline, and validate the packaged Node application. A development shell alone does not prove reproducible builds.
