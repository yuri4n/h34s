# Test your handlers

<!-- claude 2026-10-20: changed: the test helpers (ADR-0006) -->

A handler is a plain function from `Request` to a program. Test it like any other function: build a fake request, run it with `KHandler.test` or `ZHandler.test`, and check the head and the body. You need no h3, no Nitro and no server.

**Status.** `Request.fake` is new in `0.2.0-alpha.1`. `KHandler.test`, `ZHandler.test`, `TestResponse` and `Fetch.fake` are new in `0.3.0-alpha.1`; they replace the manual provisioning with `Var.runTuple` and `ZIO.stateful` that this guide showed for `0.2.0-alpha.1`.

## Keep handlers as values

Define the handler function as a value, and pass it to `AppHandler.define` (or `KHandler.define`, `ZHandler.define`) separately. The demo's ZIO handlers do this in `NotesHandler.scala`:

```scala
object NotesHandler:
    val create: Request => ZIO[HandlerEnv & Notes, Throwable, Note] = request =>
      for
        input <- request.body.json[CreateNote]
        note  <- ZIO.serviceWithZIO[Notes](_.create(input.text))
        _     <- Response.status(Status.Created)
      yield note

@JSExportTopLevel("default", "notes-post")
val createNote: EventHandler = AppHandler.define(NotesHandler.create)
```

Put services behind traits, so a test can provide an in-memory implementation.

## Build a fake request

`Request.fake` takes named parameters, all optional:

```scala
Request.fake(
  method = "POST",
  path = "/api/notes",
  headers = Map("content-type" -> "application/json"),
  query = Map("page" -> List("2")),
  routerParams = Map("id" -> "7"),
  cookies = Map("session" -> "abc"),
  body = Some("""{"text":"hello"}"""),
)
```

<!-- claude 2026-10-19: changed: `Request.fake` takes `requireJsonContentType` and follows the handler default (issue #41) -->

`development`, `debug`, `bodyLimit`, `requireJsonContentType` and `runtimeConfig` are also available. Body reads follow the same rules as a real request: the content type, the limit, invalid JSON and schema validation behave the same. Like `HandlerOptions`, `Request.fake` requires a JSON content type by default, so give a fake request with a body that you read with `json[A]` a `content-type` header. Pass `requireJsonContentType = false` to test a handler that turns the option off.

A handler that reads configuration per request with `RuntimeConfig.get(request)` (Kyo) or `ZRuntimeConfig.get(request)` (ZIO) needs the config in the fake request, as JSON text:

```scala
val request = Request.fake(runtimeConfig = Some("""{"greeting":{"salutation":"Hi"}}"""))
```

Without `runtimeConfig`, those reads fail with `ConfigError("h34s Nitro plugin is not installed")`, as they do without the h34s module. Often it is simpler to read configuration in your `AppHandler` and pass values to handlers as services.

## Kyo: `KHandler.test`

Call `KHandler.test(handler)(request)`. It provides what `KHandler.define` provides for a request: a request scope, an empty response head, a transport for `Response.sendStream` and a server-side `$fetch`. It gives a `TestResponse` with the head that your program set and the body. This example is the "guide's example" test of `HandlerTestSuite`:

```scala
val handler: Request => Greeting < HandlerEffects = request =>
  for
    input <- request.body.json[Input]
    _     <- Response.status(Status.Created)
  yield Greeting(s"Hello, ${input.name}")

val request = Request.fake(method = "POST", headers = Map("content-type" -> "application/json"), body = Some("""{"name":"Scala"}"""))
val program = KHandler.test(handler)(request)
// program: TestResponse[Greeting] < (Async & Abort[Throwable])

import AllowUnsafe.embrace.danger
Fiber.Unsafe.init(Abort.run[Throwable](program)).toFuture().map { result =>
  val response = result.getOrThrow
  assertEquals(response.status, Some(Status.Created))
  assertEquals(response.body, TestResponse.Body.Value(Greeting("Hello, Scala")))
}
```

The last part runs the program with munit, as the h34s suites do. Use your own Kyo test setup if you have one.

Provide services inside the function, with `Env.run`, as you do for `KHandler.define`. `fake` is your in-memory `Greetings`:

```scala
val handler: Request => Greeting < (HandlerEffects & Env[Greetings]) = request =>
  Env.use[Greetings](greetings => Greeting(greetings.greet(request.query.getOrElse("name", "you"))))

val program = KHandler.test(request => Env.run(fake)(handler(request)))(Request.fake(query = Map("name" -> List("Ada"))))
```

A failure of your program stays a failure of `program`. Run it with `Abort.run` to check an error, for example `Abort.run[HttpError](KHandler.test(handler)(request))`.

### Answer `$fetch` calls

`KHandler.test` uses `Fetch.unavailable` by default: a handler that calls `KHandler.$fetch` fails. Pass `Fetch.fake` to answer calls from a map of URL to response. It records every request, and a URL without an entry answers 404:

```scala
val fetch = Fetch.fake(Map(
  "/api/greeting" -> FetchResponse.Plain(200, Map("content-type" -> "application/json"), """{"data":{"message":"hi"}}"""),
))
val handler: Request => String < HandlerEffects = _ =>
  for
    greeting <- KHandler.$fetch.get[GreetingData]("/api/greeting")
    missing  <- KHandler.$fetch.raw("/api/missing")
  yield s"${greeting.data.message} ${missing.status}"

val program = KHandler.test(handler)(Request.fake(), fetch)
```

The body is `TestResponse.Body.Value("hi 404")`, and `fetch.requests.map(_.url)` is `List("/api/greeting", "/api/missing")`.

## ZIO: `ZHandler.test`

Call `ZHandler.test(handler)(request)`. It provides the `ZState[ResponseHead]`, a request `Scope` and the transport for `Response.sendStream`, and gives a `TestResponse`. Your program's typed error stays in the error channel. This example is the "guide's example" test of `HandlerTestSpec`:

```scala
val handler: Request => ZIO[HandlerEnv, Throwable, Greeting] = request =>
  for
    input <- request.body.json[Input]
    _     <- Response.status(Status.Created)
  yield Greeting(s"Hello, ${input.name}")

val request = Request.fake(method = "POST", headers = Map("content-type" -> "application/json"), body = Some("""{"name":"Scala"}"""))
for response <- ZHandler.test(handler)(request)
yield assertTrue(
  response.status.contains(Status.Created),
  response.body == TestResponse.Body.Value(Greeting("Hello, Scala")),
)
```

Provide services inside the function, as you do for `ZHandler.define`. A rejected request fails with the same error that a client would see as its status:

```scala
val handler: Request => ZIO[HandlerEnv & Greetings, HttpError, Greeting] = request =>
  for
    name     <- ZIO.fromOption(request.query.get("name")).orElseFail(HttpError(400, "name is required"))
    greeting <- ZIO.serviceWithZIO[Greetings](_.greet(name))
  yield Greeting(greeting)

val fake = new Greetings:
    def greet(name: String): UIO[String] = ZIO.succeed(s"Hi, $name")
def run(request: Request) =
  ZHandler.test(request => handler(request).provideSomeEnvironment[HandlerEnv](_.add[Greetings](fake)))(request)

for
  greeted  <- run(Request.fake(query = Map("name" -> List("Ada"))))
  rejected <- run(Request.fake()).either
yield assertTrue(
  greeted.body == TestResponse.Body.Value(Greeting("Hi, Ada")),
  rejected.left.toOption.map(_.status).contains(400),
)
```

The demo's `NotesHandlerSpec` tests its real handlers this way, with an in-memory `Notes`. The ZIO server-side `$fetch` is not in `HandlerEnv` yet, so `ZHandler.test` has no `Fetch` parameter.

## Test a streaming handler

The test helpers collect what your handler sends with `Response.sendStream`. The body is then `TestResponse.Body.Streamed(elements)`, the strings in order. The stream's resources are released when it ends, before the request scope closes, as in a real request.

Kyo:

```scala
val handler: Request => Sent < HandlerEffects = _ =>
  Response.header("content-type", "application/x-ndjson").andThen(Response.sendStream(Stream.init(Seq("1\n", "2\n"))))

val program = KHandler.test(handler)(Request.fake())
// the body of the result: TestResponse.Body.Streamed(List("1\n", "2\n"))
```

ZIO:

```scala
val handler: Request => ZIO[HandlerEnv, Throwable, Sent] = _ =>
  Response.header("content-type", "application/x-ndjson") *> Response.sendStream(ZStream("1\n", "2\n"))

for response <- ZHandler.test(handler)(Request.fake())
yield assertTrue(response.body == TestResponse.Body.Streamed(List("1\n", "2\n")))
```

A stream that fails makes the test program fail with the stream's error, as `sendStream` does in a real request.

## Read a `TestResponse`

<!-- claude 2026-10-20: changed: after sendStream, the head is the one at the call, as on the wire -->

| Member               | Value                                                                                  |
| -------------------- | -------------------------------------------------------------------------------------- |
| `head`               | The `ResponseHead` that your program set; after `sendStream`, the one at the call      |
| `status`             | `head.status`; `None` when your program set none                                       |
| `header(name)`       | The header's values after your sets and appends, joined with `", "`; names ignore case |
| `headerValues(name)` | The same values as a list                                                              |
| `cookies`            | The cookie entries that your program set                                               |
| `body`               | `TestResponse.Body.Value(value)`, or `TestResponse.Body.Streamed(elements)`            |

`head` is what your program set. For a handler that sends a stream, it is the head at the `sendStream` call, as on the wire: a change after the call does not reach the client, so it is not in `head` either. Handler defaults (`HandlerOptions.defaults`), the default content type and the envelope are added by h34s when it writes a real response, so they are not in it. Check them end to end, as described below.

## Test the wire contract

Your clients depend on the JSON shapes, the statuses and the error entries. Pin them in tests:

- **Model shapes.** Convert a value and compare the JSON text with what your clients expect: `note.toJson` (from `NativeConverter`). For a converter that describes its TypeScript type, also check `converter.wireType.describes(js.JSON.parse(note.toJson))`; see [routes and typed `$fetch`](02.routes.md#where-the-types-come-from). A schema type gives the shapes listed in [schemas](07.schema.md#kyo-wire-shapes).
- **Error entries.** Assert the exact `InvalidInput` entries, as above. They are your 422 contract.
- **Statuses and headers.** Assert `status`, `header` and `cookies` of the `TestResponse`. Remember that on failure the core keeps only `OnFailure.Keep` entries.
- **The envelope.** `{"data": ...}`, `{"errors": [...]}` and 204 come from the core and are covered by h34s's own tests. Check them end to end with an HTTP request against a running server, for example in a smoke script.

## Test configuration decoding

Decode JSON text with your config's converter, without Nitro and without `scala.scalajs.js`. The demo's `AppConfigSpec`:

```scala
val runtimeConfig =
  "{\"database\":{\"host\":\"127.0.0.1\",\"port\":5432,\"user\":\"h34s\",\"password\":\"hunter2\",\"name\":\"h34s\"}}"
val config = summon[NativeConverter[AppConfig]].fromJson(runtimeConfig)
assertTrue(config.database.password.reveal == "hunter2", !config.toString.contains("hunter2"))
```

## Test shared resources

Without the Nitro plugin, `Shared` and `ZShared` register nothing. Call `close` at the end of the test to release the resource.
