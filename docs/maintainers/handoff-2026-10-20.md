## 6. How a session runs here

<!-- claude 2026-10-20: created: the process facts a cloud session needs -->

The rules are in the "Agent sessions" section of `AGENTS.md` (models, shapes, briefs, the one-sbt rule, the annotation rule). The facts below were learned in the cloud sessions and are not written anywhere else.

- **Shapes that worked.** A feature phase is one Workflow script with three sequential agents: an implementer (Opus) that commits and does not push, one review seat (a reviewer with a numbered checklist, or the skeptic for concurrency and resource-release code, inheriting the session model), and a fixer (Opus) that applies the findings, runs the whole CI set locally, merges `origin/main` with a merge commit when `main` moved, pushes and opens the pull request with `gh api -X POST repos/yuri4n/h34s/pulls`. Each agent returns a structured object; the orchestrator reads only that and the report files. A Codex finding on a pull request whose phase has ended is a one-agent carry (Opus) in a `git worktree` under the scratchpad when the main tree is owned by the next phase; it verifies the claim with a negative control, replies on the thread before the push (`gh api -X POST repos/yuri4n/h34s/pulls/<N>/comments/<id>/replies`), pushes, and resolves the thread with `gh api -X POST repos/yuri4n/h34s/pulls/<N>/ccr/comments/<id>/resolve`. Two Codex findings of the day were refuted by reproduction (PR #71, PR #78's first round was real); a refutation goes on the thread with the traced path and to the maintainer.
- **The stop hook.** The harness's stop hook asks to commit and push whenever the tree is dirty. While a phase owns the working tree (from its first commit to its push), the orchestrator declines every time, as `AGENTS.md` says.
- **Permissions in auto mode.** A Bash `gh api` that merges a pull request or PATCHes one is denied, and so is a Bash command whose text merely mentions merging. Use the GitHub MCP tools for those: `merge_pull_request` (squash, `expectedHeadSha`, the title `<title> (#N)`), `update_pull_request`, `issue_write`, `add_issue_comment`. `gh api` works for every read, for comments, for `POST issues/<N>/sub_issues`, for review replies and for the `ccr` routes. GraphQL is blocked (`gh issue`, `gh pr` fail). The Vercel connector reads projects and deployments but cannot write project settings or create deployments.
- **Worker sessions.** `create_session` needs `source_url` and `source_revision` or the session has no checkout. Run them on Opus (`claude-opus-5-5`). A worker cannot always message the parent; read its pull request body as the report. Idle worker sessions at the handoff: `session_0148RLubrswTmWPjC5i9gpGz` (#52, done), `session_01MGckAeXLr8TFicbvgHHptB` and `session_01HAVbyUtog9uTjqShvQCMT9` (branches kept for #57).
- **Checks that CI runs, replayed locally.** The VM has a PostgreSQL 16 service; the fixers replayed the `validate`, `integration`, `postgres` (with `scripts/smoke.mjs`) and `docs / site` jobs with small shell scripts. Those scripts lived in the session scratchpad and are gone with it; the commands are the workflow steps in `.github/workflows/`. Committing a replay script under `scripts/` would save every future fixer an hour (not done; a cost-rule candidate).
- **Small traps.** Nuxt's `$fetch` and the site answer `curl`'s default `Accept` with Markdown: send `Accept: text/html` to see the page. Kyo's `Stream.map` with an effectful function emits a whole chunk at once, so a server-sent event stream wants a chunk size of one (the example does). Subagents sign commits with their own `Co-Authored-By` line; accepted, never rewritten. The spike branch `claude/adoring-carson-016y2z` must never be rebased, force-pushed or deleted: ten ADR permalinks point at it.
- **Scratch space is ephemeral.** Reports, logs and workflow scripts under `/tmp/claude-0/.../scratchpad` and `~/.claude/projects/.../workflows` do not survive the container. Everything that matters is on GitHub: the issue comments carry the evidence of every phase.
